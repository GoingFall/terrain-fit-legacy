Fit to the height field instead of to summary statistics

tools/fit_heightfield.py: vectorised model (numpy), coordinate descent on the L2 difference between
the generated heights and the reference heights. One evaluation of a 512x512 window is ~0.1 s, so a
round of 27 parameters costs seconds instead of a server run.

Result on r.0.0: rmse 53.1 -> 38.1 blocks over 10 rounds, correlation 0.64 with the reference field.

But the side-by-side (preview/hf_compare.png) shows why the picture still does not look alike: the
reference is a few large smooth slopes with terraced contours, while any fit of the current model
produces isotropic blobs crossed by river-like veins. The model has no notion of *where* a landform
is, so it cannot place the reference's massif -- no amount of parameter search fixes that.
