Server probe: generate inside the pack's own dimension (the overworld override never applied)

Four rounds of tuning were measuring vanilla terrain. A datapack cannot replace
minecraft:overworld for an existing world: the dimension comes from level.dat's WorldGenSettings,
so overriding data/minecraft/dimension/overworld.json only affects newly created worlds.

- the probe now forceloads inside the pack's own dimension (`execute in fit:fit run forceload ...`)
  and watches world/dimensions/<ns>/<name>/region
- result: the first honest measurements of the exported generator. Five rounds, all still far from
  the reference: relief reached 247 (target 238) and ridge density 273 (278), but the height
  distribution is bimodal -- a flat plain at the bottom clamp plus rare peaks, so flat 52-87%
  against 13.5% and p50 0.00 against 0.71

Conclusion: the datapack route cannot express our model faithfully. The height term's dynamic
range in game is ~5x narrower than the offline evaluator predicts, so the affine fit either
saturates the floor or overshoots, and each correction is a guess. A small mod that evaluates the
fitted model directly removes this whole class of error.
